# 路线 1｜量化研究流水线

> 数据快照 → 可信回测 → 稳健性 / 因子 → Notion 研究卡片
> 写于 2026-11-15。总览见 [`README.md`](./README.md)。

## 1. 目标与完成定义

把 Bursa-bot 现有的「每日筛选 + 6 个月回测」升级成一个能回答**「这个规则到底有没有用」**的研究底座，并把公司研究沉淀成 Notion 卡片。

全部满足才算完成：

- [ ] 快照开始之后的任意一天 D，都能重放「D 那天有哪些股票、当时看得到什么数据」
- [ ] 回测内核通过未来函数测试，并能逐笔复现生产账本
- [ ] 任何策略结论都带：样本外结果、置信区间、试过多少个变体
- [ ] Notion 里 ≤ 50 张研究卡片每天自动更新，人工写的字段不被覆盖

### 账本现在说了什么 (`docs/backtest_ledger.json`，截至 2026-11-13，扣成本后)

| 口径 | 笔数 | 平均净收益 | 标准差 |
|---|---|---|---|
| 每个信号都买，信号日在 2026-09-30 **之前** | 106 | +4.05% | 14.96% |
| 每个信号都买，信号日在 2026-09-30 **之后** | 26 (3 笔持有中) | −4.92% | 5.87% |
| 账户模式 (3 个仓位)，全部 | 25 | −0.32% | 14.31% |
| 模拟账户 (2026-09-30 起) | 11 | −2.18% | 7.59% |

怎么读：

- 9/30 之前好看、之后难看。前一段是规则定下来之前的数据 (规则是看着它调出来的)，后一段才是前向。这是过拟合或行情切换的典型样子。
- **但现在下不了结论**：后一段只有 26 笔，近期信号里亏的先出场、赚的还没走完，这个数会偏低；同一段时间的交易彼此相关，实际的不确定性比标准差算出来的更大；整个账本只统计「今天还在报告里的股票」。
- 粗算：要在 80% 把握下确认 +2% 左右的平均收益，需要约 300 个已结算信号。现在每月约 26 个信号。
- 这张表就是要建底座的理由：现有工具给得出数字，给不出可信度。

## 3. 设计决策 (已定，除非你推翻)

1. **研究层是生产的下游，不改生产。** 新的私有仓库 `bursa-research`；Actions 里多 checkout 一份 Bursa-bot (固定到某个 commit)，直接 `import engine`，读它的 `data/` 和 `docs/`。生产每天照常跑，研究层挂了也不影响报告。
2. **快照只追加、不改写。** 按交易日分区的 Parquet；每个快照带 manifest：抓取时间、来源、行数、sha256、Bursa-bot commit。
3. **两种数据分开标记。** `live` = 快照日起，时点正确；`backfill` = 一次性回补的历史 (只含今天还上市的股票，复权口径是下载那天的)。`backfill` 只能做探索，不能用来下结论。
4. **存不复权价 + 公司行动** (拆股、红股、除权)，复权在读取时算。
5. **财报的可用日期 = 公告日** (`docs/ann` 里的财报类公告)；找不到就用「季度结束 + 2 个月」，宁可晚不可早。
6. **信号由 `engine.py` 算**，跟生产一致；成交模型是独立的一层。
7. **试验登记簿**：每跑一个参数或规则变体记一行，报告里写明「共试了 N 个」。
8. **Notion 同步是确定性脚本**，不经过模型；叙述文字沿用 `docs/intel` 已经生成的事实摘要。

## 4. 阶段

### P0 数据快照 (最先做；约 2–3 个会话)

交付：
- `snapshot.py` + 一个独立 workflow，每个交易日收盘后跑一次，按交易日期去重 (同一天重跑结果一致)
- 每天存：全市场 OHLCV (不复权)、成交额、市值 / 股本、清单成员、无成交 / 停牌标记、公司行动、公告索引、当天的 `strategy.json` 和命中的信号
- 一次性回补 10 年日线，标 `backfill`
- 数据健康检查：缺失、重复 K 线、零成交、没有对应公司行动的价格跳变、日期和时区；每天输出一份健康报告
- `replay(D)`：返回 D 那天的股票清单和当时可见的数据

验收：
- 连续 5 个交易日自动跑完，无人工干预
- 同一天重跑，文件哈希不变
- `replay(D)` 对任意已存日期可用；清单里包含之后被移除的股票
- 健康报告里每一项异常都有日志

### P1 可信回测内核 (约 3–4 个会话)

交付：
- 日频事件驱动回测，读快照，调 `engine.py`
- **未来函数测试**：对每个指标和信号做截断一致性检查 (只给前 t 根算出的第 t 根 = 给全部数据算出的第 t 根)；波段低点这类要左右 K 线确认的，确认之前不能被使用
- **进场口径核查**：`strategy.json` 现在是 `entry_close: true` (信号日收盘价进场)。这只有在「收盘前算出的信号 = 收盘后的信号」时才做得到。同时跑「信号日收盘」和「隔天开盘」两种口径，量出差多少
- **成交模型**：最小跳动取整、一手 100 股、单笔占当日成交量上限、跳空、涨跌停和停牌无法成交、低价股跳一格的成本；成交失败要写原因
- **成本**：佣金 0.1% (最低 RM8)、结算费 0.03%、印花税每 RM1,000 收 RM1 — 动手时按现行规则再核一次
- **账本对账**：用同一份数据逐笔复现 `docs/backtest_ledger.json`，差异逐条解释
- pytest + PR 上自动跑的 CI；合成数据测试 (埋一个已知效应看能不能找回来；不埋效应看误报率)
- 每次回测输出 run manifest：代码 commit、策略签名、数据快照范围、成本参数

验收：截断测试全过；账本差异为 0 或每条有解释；合成数据测试通过；两种进场口径的差异有数字。

### P2 稳健性与因子 (约 3–4 个会话)

交付：
- 样本外：前向模拟账户继续累计 (唯一真正的样本外)；walk-forward 用 `backfill` 数据，只作参考
- Bootstrap 置信区间，按信号日分块 (同一天的几笔一起抽)
- 参数敏感性热力图；基准对照：同期任意一天买进 (账本里已有)、全池等权、KLCI
- 因子模块：动量 (1 / 3 / 6 / 12−1 个月)、短期反转、波动率、Amihud 流动性、距 52 周高点、放量。输出 IC、分组收益、换手、扣成本后的收益；按 Main / ACE、价格档、流动性档分层。市值和估值类因子等快照累计够了再做
- 自动生成的「策略体检报告」：交易笔数、样本区间、成本、最大回撤、获利因子、期望值、MFE / MAE、样本外表现、置信区间、试验次数

验收：体检报告一条命令生成；没有样本外结果的策略自动标「未验证」；试验登记簿里的行数 = 实际跑过的变体数。

### P3 Notion 研究卡片 (约 2 个会话)

数据库字段：

| 字段 | 类型 | 来源 | 谁写 |
|---|---|---|---|
| 公司 | 标题 | `data/watchlist.json` | 机器 |
| 代码 | 文本 (同步的键) | 同上 | 机器 |
| 板块 / 行业 | 选项 | `docs/stock` 的 `profile` (有才填) | 机器 |
| 市值 | 数字 | 快照 | 机器 |
| 最新季度 | 日期 | `docs/stock` 的 `fin` | 机器 |
| 营收同比 / 净利同比 | 数字 | 程序算 | 机器 |
| 近况 / 重要事件 / 留意事项 | 文本 | `docs/intel/<代码>.json` | 机器 |
| 下一个日期 | 日期 | `docs/intel/calendar.json` | 机器 |
| 信号状态 | 选项：无 / 今日信号 / 模拟持仓 | 账本 | 机器 |
| 数据日期 | 日期 | 同步时间 | 机器 |
| 状态 | 选项：待读 / 跟踪 / 归档 | — | **你** |
| 我的判断 | 文本 | — | **你** |
| 下次复核 | 日期 | — | **你** |

页面正文是一张事实表：`事实 | 数值与单位 | 来源链接 | 发布日`，沿用你现有的事实卡格式。

同步规则：以代码为键新增或更新；机器字段可以覆盖，「你」的三个字段永远不碰；每条事实必须带来源链接和日期，没有来源的不写；不出现利好 / 利空 / 买卖字眼 (沿用 `company_intel.py` 的过滤)。

验收：连续 5 天自动同步；手动改过的字段没被覆盖；随机抽 5 张卡片对照公告原文，事实和日期一致。

### P4 运维 (持续)

- 每月重算体检报告
