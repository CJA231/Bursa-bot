## 1. 三条路线怎么拼在一起

```
Bursa-bot (公开仓库，生产，每个交易日自动跑)        ← 日常流程一行都不动
   │  engine.py · strategy.json · docs/stock|ann|intel · backtest_ledger.json
   ▼
路线 1  研究底座 (建议放新的私有仓库)
   每日全市场快照 → 可重放的回测 → 稳健性 / 因子 → 研究卡片 → Notion
   │ 数据 + 回测内核                        │ 研究卡片 (markdown / JSON)
   ▼                                        ▼
路线 3  研究成果                          路线 2  本地 AI (你的电脑)
   预登记 → 检验 → 独立复算 → 报告           模型服务 + 评测集 + 检索问答
```

- 路线 1 是底座。路线 3 的量化课题、路线 2 的检索语料都从它来。
- 路线 2 跟另外两条**没有硬依赖**，可以平行做，也可以晚做。
- 路线 3 的估值课题 (线 B) 不依赖路线 1，随时能开始。

## 2. 先后顺序 (为什么这样排)

1. **路线 1 的 P0 (数据快照) 排第一。** 全市场每天的股票清单、不复权价格、市值、公告，过了那一天就补不回来；现在回测的幸存者偏差就是因为没有这份历史。晚一天开工就少一天数据。
2. **路线 3 的课题 A1 研究卡排第二。** 判定规则必须在看到更多前向数据之前写死并提交，越早越干净。
3. **路线 1 的 P1 (可信回测内核)。** 没有未来函数测试和账本对账，后面任何数字都不可信。
4. 路线 2 的 L0–L2 (盘点、模型服务、评测) 随时可以插进来，半天到两天一段。
5. 路线 1 的 P2–P3、路线 3 的检验和写作、路线 2 的 L3–L4 往后排。

## 3. 八周节奏 (业余时间；会话数是估计)

| 周 | 路线 1 | 路线 3 | 路线 2 | 需要你本人做的 (每周 ≤ 3 件) |
|---|---|---|---|---|
| 0 | — | — | — | 回答下面第 5 节的决定；建私有仓库 |
| 1 | P0 快照上线 | A1 研究卡提交 | L0 盘点 | 加 Secrets；看第一次快照日志；确认研究卡 |
| 2–3 | P1 回测内核 + 测试 | (等数据) | L1 模型服务 | 看账本对账的差异清单；合并 PR |
| 4–5 | P2 稳健性 + 因子 | A1 中期数字；线 B 估值案例 | L2 评测 + 路由表 | 给评测题打分；确认路由表 |
| 6 | P3 Notion 研究卡片 | A1 独立复算 | — | 建 Notion 集成；抽查 5 张卡 |
| 7–8 | P4 周报 | 写报告 + 追问演练 | L3–L4 检索问答 | 读报告；回答 20 个追问 |

哪一周没空就整体顺延，但 P0 不要拖：它上线之后是自动跑的，不占你时间。

## 4. 模型分工 (贵的模型只做贵的事)

| 工作 | 用什么 | 原因 |
|---|---|---|
| 所有数字 (回测、统计、财务比率) | 确定性代码 | 模型不手算数字；报告里的数字只来自代码生成的结果表 |
| 架构、回测内核、未来函数测试、研究设计、对抗式复核 | 高端模型的长会话 | 错一处后面全错，值得花钱 |
| 每晚的公司资讯摘要、公告分类 | 现有的 DeepSeek 流水线 | 已经在跑，量大、单价低 |
| 私密材料、离线、批量抽取 | 本地模型 (路线 2 评测通过的任务才放过去) | 隐私；质量以评测为准 |
| 并行子任务 (写测试、逐模块检查) | 子 Agent，按需开，几个就够 | 每开一个都要重新读上下文，开多了只是烧钱 |

## 6. 怎么交接

1. 每个路线文件最后有**开工提示词**，开新会话时整段贴进去。
2. **一个会话只做一个阶段**，做完停下来等验收；验收没过不进下一阶段。
3. 每个会话结束前更新该路线文件的**进度记录**并提交：做了什么、没做什么、卡在哪、下一步。
4. 新会话先读 `handoff/README.md` + 对应路线文件 + `bursa-bot.md` 第 7、8 节，再动手。
5. 路线文件在本仓库 `handoff/`；如果还没合并到 `main`，在分支 `claude/cool-tesla-rwk4ga`。

## 7. 所有路线通用的护栏

- **PR 由仓库主人自己 merge；没被要求不开 PR；问过而没被选中的选项就是不做** (`bursa-bot.md`「协作规矩」)。`Bursa.yml` 不删也不提。
- **生产不受研究影响**：不为研究改 `main.py`、`daily.yml`、`docs/` 的输出。研究层是下游，只读生产的文件。
- **不写买卖建议**：卡片、报告只陈述事实和统计结果，不出现利好 / 利空 / 买入 / 卖出。收费化是另一条线，不混进来。
- **数据使用**：Yahoo Finance、KLSE Screener 的数据只限个人使用，原始数据不公开再分发；要公开的只有代码、汇总结果和图。
- **密钥**只放 GitHub Secrets 或本机环境变量，不进仓库、不进聊天。
- **沙箱限制**：云端会话连不上 Yahoo / Bursa / KLSE Screener，真实数据只能在 GitHub Actions 上验证；本地用假数据测逻辑。
- **没有样本外验证的策略不标「有效」。**
- 给操作步骤时按手机界面写。

## 8. 已知的交接缺口

- `bursa-bot.md` 的内容停在 2026-09-30 前后。之后做的终端版、公司资讯 (`scripts/company_intel.py`)、新股日历 (`ipo_calendar.py`)、股票池存档、owner 网页编辑、公开展示站，只在 `README.md` 里有说明。接手 Bursa-bot 本体的会话两份都要读。
- 仓库没有任何自动测试，也没有 CI。路线 1 的 P1 会补上研究层的测试，生产代码的测试不在这三条路线里。
