# 路线 2｜本地 AI 工程

> 模型服务 → 自己的评测集 → 带出处的本地检索问答 → 接入日常
> 写于 2026-11-15。总览见 [`README.md`](./README.md)。
> 这条路线在**你自己的电脑**上做，云端会话看不到那台机器。

## 1. 目标与定位

先说它是什么、不是什么：

- 本地模型的价值是**隐私** (个人财务、求职材料、没公开的研究)、**离线可用**、**练手**。
- 它**不是为了省钱**。现有流水线用的云端低价模型按量计费已经很便宜，同等硬件下本地模型的质量通常不如它们。
- 所以哪些任务放本地，由**评测结果**决定，不由感觉决定。

全部满足才算完成：

- [ ] 一台机器上稳定跑着模型服务，只监听本机
- [ ] 一份用自己真实材料做的评测集，和一张路由表 (哪类任务用本地 / 低价云端 / 高端云端)
- [ ] 能回答「某公司最近披露了什么」并给出处的本地检索问答；库里没有的会说没有
- [ ] 重建索引一条命令，换模型后重跑评测一条命令

**未核实。** 硬件、系统、已经装了什么，接手的会话第一步自己查 (L0)。不要按聊天里提过的配置直接假设。

## 3. 设计决策 (已定，除非你推翻)

1. **先评测，后买硬件。** L2 的数据指出瓶颈是显存、且换硬件确实能解决，才讨论升级。
2. **模型服务用 Ollama** (OpenAI 兼容接口)，只绑 `127.0.0.1`，不开放给局域网或公网。
3. **模型按档位选，不写死型号。** 型号更新很快，动手那天查当时的模型库，在档位内选 2–3 个用评测集比。粗估 (4-bit 量化，以实测为准)：

   | 可用显存 / 统一内存 | 能流畅跑的规模 |
   |---|---|
   | 8 GB | 7–9B |
   | 12 GB | 12–14B |
   | 16 GB | 14–20B，或小一档换更长上下文 |
   | 24 GB 以上 | 27–32B |
   | Apple 统一内存 16 / 32 GB | 7–9B / 14–27B |

4. **三个角色**：多语言 embedding 模型 (中英混合，例如 bge-m3 这一类)、做抽取和分类的指令模型、可选的 reranker。
5. **显卡兼容性**：NVIDIA 走 CUDA；AMD 显卡看当时 Ollama 的支持列表，不在列表里就用 Vulkan 后端的工具或退回 CPU；Apple 芯片走 Metal。以动手当天的官方文档为准。
6. **检索问答保持小而可查**：纯 Python + 本地向量库 + 关键词检索混合。股票代码、数字、公司简称必须精确命中，只用向量检索会漏。不上重框架。
7. **回答必须带出处** (文件、标题、日期)；检索不到就回答「没有找到」，不许编。
8. **上下文长度要显式设置**：默认的上下文窗口可能比模型支持的小得多，超出的部分会被悄悄截断、不报错。设好之后在评测里验证。
9. **笔记库是一个纯 markdown 文件夹** (用不用 Obsidian 打开都行)。Notion 是执行台和手机入口；markdown 库是本地可检索的语料。**只做单向**：路线 1 的研究卡片导出成 markdown 镜像放进库里；不做 Notion ↔ 笔记库的双向同步。

## 4. 阶段

### L0 盘点 (约 30 分钟)

交付 `ENV.md`：系统版本、CPU、内存、显卡型号和显存、可用磁盘、已装的 Ollama / LM Studio / Python / Git 及版本。
验收：你看过并确认用哪台机器。

### L1 模型服务 (约半天)

- 安装或升级 Ollama；按档位拉 1 个指令模型 + 1 个 embedding 模型
- 测速：每秒输出 token、首字等待、显存占用，记进 `ENV.md`
- 确认只监听本机；确认模型文件放在空间够的盘

验收：一条 `curl` 调通接口；测速表填好。

### L2 评测集与路由表 (约 1–2 天)

三类任务，各 10–20 题，**全部来自你自己的真实材料，都有标准答案**：

| 类 | 任务 | 标准答案从哪来 |
|---|---|---|
| A | 公告抽取：给公告原文，抽出日期、金额、事件类型 | Bursa-bot `docs/intel/<代码>.json` 的 `facts`，人工对照原文核过才能当答案 |
| B | 中英摘要 / 改写 | 人工打 1–5 分 |
| C | 检索问答：给问题，应该命中哪份文件 | 自己标 |

每个模型 (本地候选 + 一个低价云端 + 一个高端云端) 记录：正确率、格式合格率、耗时、费用、需要返工的比例。结果同时记进你自己的实测记录表，不另建一份。

产出**路由表**：每类任务用哪一档模型，依据是哪几行数据。

验收：评测脚本一条命令重跑；路由表你确认过。

### L3 检索问答 v1 (约 2–3 天)

- 入库：markdown 笔记、研究卡片 (JSON 或 markdown)、PDF 的文字层。表格和扫描件先不处理，在文档里写明
- 按标题切块；向量 + 关键词混合检索；命令行查询，回答带出处

验收：
- 20 道检索题，前 5 条结果里命中正确文件的比例 ≥ 80%。达不到先查切块和检索，不要先换模型
- 故意问 5 道库里没有的问题，全部回答「没有找到」

### L4 接入日常 (约 1–2 天)

- 路线 1 的研究卡片定期导出成 markdown 镜像
- 一个 `ask` 命令
- 可选：把检索包成 MCP 工具给 Claude Code 用。注意这样检索到的片段会发到云端，**私密文件夹默认排除**

### L5 维护 (持续)

- 每周增量索引
- 换模型必须重跑 L2，分数掉了就不换
- 备份 = 笔记库 + 配置；索引可以重建，不用备份

## 5. 护栏

- 评测结果出来之前不买硬件
- 模型服务不暴露到局域网或公网
- 私密文件夹 (财务、证件、求职) 单独索引，默认不进任何会发往云端的流程
- 本地模型的输出不直接进研究结论或对外内容，先过人工或高端模型复核
- 改系统级设置之前先问：驱动、BIOS、分区、删除大量文件、全局环境变量
- 研究用的数字不由本地模型产生，只来自代码

## 7. 怎么开工

在那台电脑上装 Claude Code，新建一个空文件夹 (例如 `local-ai`)，把本文件放进去，贴下面这段。

```
你在接手「路线 2：本地 AI 工程」，工作目录就是这台电脑上的这个文件夹。
先读本目录的 route2-local-ai.md。

本次只做阶段 L0 (盘点)，做完停下来等我确认。

要求：
1. 只读不改：查系统、CPU、内存、显卡和显存、磁盘、已装的 Ollama / LM Studio / Python / Git，写成 ENV.md。
2. 不安装、不卸载、不改任何系统设置；需要管理员权限的命令先问我。
3. 结束前在 route2-local-ai.md 的「进度记录」写：查到了什么、哪些没查到、建议用哪个档位的模型。
```

后面的阶段把「L0 (盘点)」换成对应阶段，并去掉「只读不改」那一条。
